**Root cause: the ±1 GB memory threshold is tighter than the metric's own
run-to-run variance.** Three lines of evidence:

1. **No code delta.** The previous run of this job (26 h earlier,
   [run 33210244232](https://github.com/verl-project/verl/actions/runs/33210244232),

   contains exactly one commit, #7595, touching only
   `examples/grpo_trainer/run_qwen3_30b_veomni.sh`. Nothing on this job's path
   changed.
2. **The peak tracks the token load of the heaviest step.** In both runs the
   high-water mark is set at step 5, and step 5 is the heaviest step of all 15:

   | | step-5 `global_seqlen/balanced_max` | peak `max_memory_allocated_gb` |

   activation memory per token, consistently, in two different steps. Step 1 is
   near-identical across runs (38.4990 vs 38.4469).
3. **The token load is rollout-driven, hence stochastic.** The script
   (`tests/special_npu/run_qwen3_vl_8b_Instruct_fsdp2_npu.sh`) does not enable
   `actor_rollout_ref.rollout.full_determinism` (default off, and `main_ppo.py`
   only sets the determinism env vars when it is on), so sampled response
   lengths — and with them the per-step token counts and the peak — differ on
   every run.

   ([Aug 26, job 98269413520](https://github.com/verl-project/verl/actions/runs/32997187200/job/98269413520)),

   (recipe commit 45780547, Aug 26) was taken from a high-side run, so the
   check fails whenever the draw lands low.

sets `ppo_mini_batch_size=8` over 8 GPUs with

worth −27 GB.)

**Verdict: BASELINE_REGRESSION** (checking-script metric miss, no crash, no
verl defect). No branch pushed — the fix belongs in
`verl-project/verl-ascend-recipe`, outside this kit's push boundary:
regenerate `baseline_qwen3_vl_8b_Instruct_fsdp2_npu.txt` from a mid-range run
(B=45.43 sits at the top of the observed band), or relax the memory threshold
to ±2.5 GB / make it one-sided (only memory *growth* is a capacity risk).
Enabling `full_determinism` in the nightly script would also stabilise the
metric, but it changes what the nightly measures and would invalidate the
throughput baseline — a maintainer decision, not an auto-prepared patch.
