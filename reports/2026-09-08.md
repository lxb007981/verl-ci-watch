## New failures

### Router-replay registry regression (#7106) — 4 Megatron jobs

Affected: [quick_start_qwen3_0_6b_megatron_vllm_ascend](https://github.com/verl-project/verl/actions/runs/34150398515/job/101831291862)
(job 101831291862), [nightlyCI_gspo-qwen3-30b-megatron-vllm_ascend](https://github.com/verl-project/verl/actions/runs/34150398515/job/101831291888),
[quick_start_qwen3_0_6b_megatron_sglang_ascend](https://github.com/verl-project/verl/actions/runs/34150398515/job/101831291947)
(all run [34150398515](https://github.com/verl-project/verl/actions/runs/34150398515)),
and [nightlyCI_grpo-qwen3-30b-megatron-sglang_ascend](https://github.com/verl-project/verl/actions/runs/34146606227/job/101819898833)
(run [34146606227](https://github.com/verl-project/verl/actions/runs/34146606227)).
All four died at the **first `compute_log_prob` forward pass**, before training
step 1 (the checking script never ran; nothing to do with metrics).

Evidence (r34150398515_quick_start_qwen3_0_6b_megatron_vllm_ascend.log, 18:17:34;
identical in the other three logs):

```
trainer_base.py:564 _step_once -> _compute_old_log_prob
  -> compute_log_prob -> infer_batch -> forward_backward_batch
transformer_impl.py:1297 in forward_step
    if RouterReplayHelper.is_replay_backward_action(self.tf_config, vp_rank):
router_replay_utils.py:745 in get_micro_batch_router_list
    raise RuntimeError(
RuntimeError: cannot map router replay registry to the current PP/VPP stage:
registry=0, local_pp_routers=14, global_routers=28, pp_rank=0, vp_rank=0
```

Dense jobs (Qwen3-0.6B, PP=2) report `local=14, global=28`; the two MoE jobs
(Qwen3-30B-A3B) report `registry=0, local_pp_routers=48, global_routers=48` —
proving the failure is "replay disabled", not "dense model".

Root cause — regression from **#7106** (`c80729fb`, "preserve R2 router replay
for THD-packed batches", merged ~11:30 UTC Sep 7; tonight is the first NPU
nightly on it):

- `RouterReplay` instances register into the process-global registry **only
  when router replay is enabled** on the config
  (`apply_router_replay_patch` gates `TopKRouter` patching on
  `enable_routing_replay` / `moe_enable_routing_replay`). None of the nightly
  jobs enable it (it is opt-in) → registry is legitimately empty (`registry=0`).
- #7106 replaced the old benign behavior (slicing an empty registry → `[]`,
  which every `is_*_action` caller already treats as "no replay action") with
  a hard error whenever the registry size matches neither the local nor the
  global MoE-layer count.
- `forward_step` (transformer_impl.py:1297) calls `is_replay_backward_action`
  **unconditionally** — replay enabled or not — so the raise fires at the
  first forward.
- `is_moe_layer` counts via `moe_layer_freq`, whose Megatron default is `1`
  even for dense models, so dense Qwen3-0.6B counts 28 "MoE" layers →
  `0 ≠ 14` and `0 < 28` → raise.

Causality checks: all four jobs were green the previous night on `23af6a7a`;
of the five commits in `23af6a7a..d040717b` only #7106 touches this path
(#7740 MLflow, #7643 continuous_token, #7728 A5 IPC weight transfer, #7779
GLM-only `npu_vllm_patch.py`); the non-Megatron nightly jobs (FSDP/veomni)
were green on the same `d040717b` in run [34154672131](https://github.com/verl-project/verl/actions/runs/34154672131).
`gh search` shows no open issue/PR tracking this.

Verdict: **VERL_BUG**, high priority — every Megatron nightly stays red until
it lands.

**Fix pushed:** `ci-fix/router-replay-empty-registry` (head `a56f3ec7`, on
`d040717b`) — early-return `[]` in `get_micro_batch_router_list` when the
registry is empty (restores the pre-#7106 contract), keeps #7106's strict
error for non-empty un-mappable registries, plus a CPU regression test.
Validated by log analysis, `py_compile`, and direct execution of the fixed
function with stubbed torch/megatron imports (empty → `[]`; local-only
registry → correct slice; ambiguous non-empty registry → still raises;
`is_*_action` falsy; VPP variant → `[]`). **No NPU validation** — the four
nightly jobs above must get past `compute_log_prob` and train 15/15 to
confirm.
