### quick_start_qwen3_0_6b_fsdp2_vllm_ascend — [run 37353791417](https://github.com/verl-project/verl/actions/runs/37353791417), [job 111910945484](https://github.com/verl-project/verl/actions/runs/37353791417/job/111910945484)

Only genuinely new item tonight — a known failure class firing on a job it has not hit before.

- **Evidence** (`r37353791417_quick_start_qwen3_0_6b_fsdp2_vllm_ascend.log`): model/tokenizer loaded fine (tvqbd, OLD cached pool); died ~9.5 min in at vLLM engine init, before any training step. The job's colocated vLLM servers (pids 16963/16964/16966, TP2 ×2) started concurrently at 18:19:04; at 18:19:44 Worker pid=18149:
  ```
  worker_main -> WorkerProc.__init__ -> init_device
  -> vllm_ascend/worker/worker.py:992 _init_worker_distributed_environment
  -> vllm parallel_state.py:1609 init_distributed_environment -> TCPStore
  torch.distributed.DistNetworkError: The server socket has failed to listen on any
  local network address. port: 43679, ... name: EADDRINUSE, message: address already in use
  ```
  → `Exception: WorkerProc initialization failed due to an exception in a background process` → EngineCore exit, job exit 1 at 18:20:00 (log:2468, 2498). Check step never ran.
- **Root cause:** the intra-node init-port race — single-node MultiprocExecutor vLLM picks the `init_process_group` port itself via `get_open_port()` (bind throwaway socket, release, bind later); two engines starting on one node can pick the same port in the gap. Co-locants on tvqbd at that moment: this job's own second server, the sibling pack (megatron_vllm exited 18:18:52, fsdp2_sglang green until 18:20:10) — either racer is the same class.
- **Upstream:** tracked as open issue [verl#6677](https://github.com/verl-project/verl/issues/6677) "Multiple vLLM instances on the same node may choose the same distributed init port and fail with EADDRINUSE" (still open, verified today). Maintainer response there: vLLM ignores externally provided ports on this path, so verl cannot fix it ("This isn't fixable in verl"). This race previously killed qwen3_vl on 2026-09-02, 09-07 and 10-01; tonight is its first hit on a quick_start job.
- **verl exonerated:** main `8718ca30` byte-identical to the green nights of 10-02→10-05 for this job in the same 4-job tvqbd packing.
- **Verdict: KNOWN (#6677).** Action: none in verl; retry is the mitigation (rare race).
